# 2026-11-10 商品快照更新修复

## 根因

新机 AkShare `futures_foreign_commodity_realtime` 不仅请求行情，还抓取新浪 HTML 获取合约名称、人民币换算和汇率。附加页面解析持续报 `list index out of range`，导致整个外盘行情刷新失败。缓存保留了 11 月 5 日最后一次成功值。原导出虽标记 stale，仍把旧 `change_pct` 留在正常涨跌字段，容易被日报误用。

## 变更

- 改为腾讯公开 `hf_CL / hf_OIL / hf_GC / hf_SI / hf_HG` 批量报价，不依赖 HTML、名称表或人民币换算，不绕过原站拒绝访问。
- 保留提供方日期/时间（北京时间），采集完成时间单独记录。原油美元/桶，黄金白银美元/盎司，铜美分/磅，未乘错 100 倍。
- 涨跌幅由最新价相对提供方上一结算价计算，明确 `change_basis`。不冒称自然日零点回报；到期合约编号未提供，记录为 provider rolling quote，而不是承诺某个具体到期合约。
- 正常 15 分钟后台刷新保持不变。日报和首次周/月归档前另做仅商品的刷新，失败保留上次成功值及成功时间，不把尝试时间写成成功时间，也不因单一商品源失败阻断其他市场。
- 写缓存采用共享锁与原子替换；慢任务不能用旧商品覆盖新成功报价。
- Agent 导出将超过 2 小时、未来时间、缺少时区、采集过期等观测标为 stale。与北京时间报告日期不同的商品也不用于当日涨跌。休市时可保留上次真实报价，但不冒充当天行情。
- `change_pct=null`、`eligible_for_daily_change=false` 是硬性保护；`reported_change_pct` 仅保留原始观测供审计。质量审计会拒绝仍携带可用涨跌幅的过期记录。
- 未修改前端模板/交互、TG 消息格式、筛选算法和配额。

## 当日版本化修订

`agent/v1/history/2026-11-10.json` 只替换五条 futures 观测及其健康汇总。股票、加密、其他宏观原始价格不重生成。原 JSON 和健康报告保存在 `agent/v1/revisions/2026-11-10/`，修订记录保留原生成时间、原 SHA256、新采样时间与变更范围；禁止向过去日期灌入当前行情。

线上验收：五条真实观测时间为北京时间 19:56:34–19:57:01，成功采集时间为 19:57:22；`source_checked_at` 使用等价 UTC 表达 `2026-11-10T11:57:22+00:00`，不等同于行情观测时间。五条 stale=false，数据分支重新拉取回读与本地文件一致。

测试覆盖报价解析、单位、结算基准、无效/未来/残缺响应、旧行情硬屏蔽、逐项采集时间、失败保留原成功时间、并发慢写保护、仅商品历史修订以及审计门禁。
