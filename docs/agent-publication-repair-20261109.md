# 2026-11-09 新机快照发布修复

## 已确认的根因

1. 新机一次性行情缓存 `data/cache/cache.db` 损坏。真实行情成功返回后，缓存写入异常仍使整个获取任务失败；Heatmap 吞掉获取异常，调度统计误记为成功。不能据此断言云迁移或具体复制动作造成了损坏。
2. 美股 EOD 日期是次日入库键，历史日线回填日期却已经是交易日。导出对两者一律减一天，错误地把周五归为周四。DB 写入时间也不是交易所观测时间。
3. 日报允许若干自然日延迟，周报则按自己的最新样本判断当前，没有对齐最近已完成 NYSE 交易日。
4. 趋势行情校验只接受 Finnhub，拒绝新机已可用且具有纽约常规交易时间的腾讯回退。
5. 三个独立发布尝试分别发送相同故障告警，没有跨进程、按日期/故障去重。

## 修复边界

- 缓存读写失败降级为不使用缓存，不丢弃上游真实结果。损坏目录整份保存在服务器 `/root/migration-20261109/cache-corrupt-preserved`，没有删除；持仓 ledger/meta 不参与缓存替换。
- `modules/market_sessions.py` 明确区分日线来源、正常收盘、半日市、DST 和非交易日。使用已核实的 NYSE 2026–2028 日历；未知年份明确失败，不套用银行节假日。
- 发布前批量采集具有真实纽约观测时间的最近完整美股收盘；至少 10 条且覆盖本地 120 日跟踪池一半，否则不假装齐备。同一 session 文件复用，DB 只插入缺失行，绝不覆盖既有价格；保存原始代码、来源、观测时间和采集时间。
- 日报严格匹配最近完整美股交易日；周/月报按真实交易日对齐历史序列、基准与缺口，不对厂商历史日期二次减一天。小样本最新日期不能掩盖覆盖不足。证券别名去重沿用已验证的市场/证券类型规则。
- 周/月报发布前也准备相同的已核验收盘，不依赖周末当天恰好运行日榜。
- 同日同模式同故障跨进程去重，失败发送可重试；故障恢复后仅发一条运维恢复通知。市场信号消息模板完全不参与此逻辑。
- 未核实美股指数成交额单位，导出为 `null` 并注明原因，不把指数点位乘成交量当美元成交额。市场广度源失败保留 `null`，不拿候选池代替全市场。
- 工作日首发 19:12；19:40、19:55 独立重试保持不变。周/月报 09:30 准备、10:00 报告约定不变。
- 无前端模板、交互、TG 行情模板或筛选/配额参数变更；没有补发过期行情信号。

## 恢复结果与历史修订

- 2026-11-09 日报首次成功发布于 21:59，北京时间。A/H 使用 11-09、美股使用 11-06；1436/1447 个原始历史跟踪代码核验通过。并不代表全美股覆盖。
- 明确从 `origin/agent-data` 回读并核验 JSON、路径、归档日期及关键结构。
- `agent/v1/weekly/2026-11-08.json` 仅修订美股部分：保留原报告截止时间、A/H/商品、Crypto 和 Macro；允许标注明确的事后真实周五收盘恢复，不使用周一价格。原件存入 `agent/v1/revisions/weekly/2026-11-08/`。
- 当日日报只追加明确的元数据修订，保留所有选中价格；原日报和健康报告保存在 `agent/v1/revisions/2026-11-09/`。
- 修订工具须显式调用。正常定时生成仍冻结不可变，不自动重写过往文件。

## 验证

离线测试：Agent 导出、历史修订、质量门禁、证券身份去重、Git 首次推送失败后重试与远端回读；NYSE 周末/假日/半日市/DST；损坏缓存失效开放；Heatmap 获取异常上报；行情回退及原相对强度/收益对齐回归。

线上检查：缓存 `quick_check=ok`；真实美国证券目录 7127 行；真实收盘覆盖 1436；日报与周报 GitHub 分支回读；服务 active；重复运行同日发布复用归档，不再采集或改变冻结价格。

仍有真实缺失：独立全市场广度接口可能超时；复权口径尚未核实的历史序列、部分历史成交额、部分宏观观测仍按原规则标注 partial/null/stale。不能把发布恢复解读为这些字段已全部补齐。
